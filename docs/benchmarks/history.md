# 최적화 이력과 해석의 한계

[벤치마크 진입점](../benchmark.md) · [전체 CSV 목록](results.md) · [보관 원문](legacy-notes.md)

## 판단

보존 자료는 단계별 실험 과정을 설명하는 자산이다. 서버와 로컬, 서로 다른 데이터 시점, 시나리오 세트가 섞여 있으므로 하나의 연속된 성능 점수로 합치지 않는다. 아래 단계 이름은 당시 기록의 설명이며, 개별 측정에 대응하는 정확한 배포 커밋·DB 스냅샷·계측 로그는 CSV에 없다.

## MA 엔진 전후의 관측값

| 환경 | 시나리오 | 이전(s) | 이후(s) | 관측 시간 감소 |
|---|---|---:|---:|---:|
| 서버 | Light 2 · Minute Cross | 30.116 | 19.098 | 약 36.6% |
| 서버 | Light 4 · Minute Convergence Point | 28.569 | 15.355 | 약 46.3% |
| 로컬 | Light 2 · Minute Cross | 2.942 | 1.493 | 약 49.3% |
| 로컬 | Light 4 · Minute Convergence Point | 2.969 | 1.522 | 약 48.7% |

서버는 `20260808_213722` → `20260809_000809`, 로컬은 `20260808_215546` → `20260808_222427` CSV를 사용했다. 감소율은 `(이전 - 이후) / 이전`이다. 각 쌍의 해당 행은 종목 수가 같지만, 이것만으로 동일 DB 스냅샷·동일 요청 결과 집합을 입증하지는 못한다. 이 비율을 모든 필터의 보장 성능으로 일반화하지 않는다.

## 기존 문서에서 바로잡은 부분

| 과거 서술 | 확인한 근거와 현재 표현 |
|---|---|
| 첫 로컬 인메모리 Heavy 2가 약 16.5초 | 첫 파일은 27.388초다. 16.500초는 다음 AST 비용 정렬 기록이다. |
| 서버 복합 시나리오가 전부 0.6초 이내 | 08-06 Heavy 3은 0.641초다. 해당 묶음의 범위는 0.368~0.641초다. |
| 60초 타임아웃 대비 99% 이상 성능 개선 | 실패가 발생한 시각은 완료 시간 기준선이 아니다. 후보 축소·외부 랭킹·데이터 변화도 있어 일반 개선율로 사용하지 않는다. |
| 인메모리 도입으로 Disk I/O 0, 스왑 원천 차단 | CSV에 I/O·RSS·스왑 계측이 없다. 구현 의도와 관측 결과를 분리하고 효과는 미검증으로 둔다. |
| 0.1초 미만이면 비정상, 수 초~30초면 정상 | 시간만으로 판정할 수 없다. 유효한 빈 집합도 가능하며 개선판 OR 관측은 43.074초다. 계약·완료 이벤트·정답 근거를 확인한다. |
| 현재 전체 주 DB가 인메모리 | 현재는 디스크 OHLCV 정본 + MA 전용 인메모리다. [DB 문서](../database.md)를 따른다. |
| 기본 실행 대상이 과거 운영 주소 | 확인한 main 실행기 기본값은 로컬이다. [재현 절차](harness.md)는 `--host`를 명시한다. |
| CSV의 Success가 검증 통과 | main 실행기는 SSE 오류·완료 없는 종료를 Success로 남길 수 있다. 과거 모든 실행기 버전은 미복원 상태이므로 결과 파일 문자열과 독립 검증을 구분한다. |

## 남아 있는 한계

- CSV는 시나리오명·시간·종목 수·상태 네 열뿐이다. 요청 payload와 정확한 실행 코드·서버 커밋을 직접 보존하지 않는다.
- 환경 사양과 단계 설명은 당시 문서에서 가져왔다. 메모리 1GB 안에서 실제 최대 RSS가 얼마였는지 검증한 기록은 아니다.
- 실행별 반복·분산·워밍업·동시 수집 상태가 기록되지 않았다. 작은 차이는 측정 흔들림일 수 있다.
- HTTP 504 관측은 해당 요청의 실패다. 원인이나 정상 완료 시 걸릴 시간은 별도 로그 없이는 알 수 없다.
- [아키텍처 문서](../architecture.md)의 SQLite 이전 전후 미시 측정은 별도의 역사적 기록이다. 위 HTTP/SSE CSV와 같은 측정으로 합산하지 않는다.

원문을 삭제해서 불일치를 숨기지 않고 [과거 설명](legacy-notes.md)으로 보관했다. 이후 검증에서 근거가 추가되면 이 문서의 판단과 해당 결과 기록을 함께 갱신한다.
