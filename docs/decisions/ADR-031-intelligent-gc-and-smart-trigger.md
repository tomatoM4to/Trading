# ADR-031: 지능형 가비지 컬렉션 (Intelligent GC) 및 스마트 트리거 도입

## Status
Accepted (Supersedes ADR-030)

## Date
2026-08-12

## Context
ADR-030에서 결정한 "단순 캘린더 날짜 기준 일괄 삭제(Time-based Bulk GC)" 정책은 치명적인 맹점이 있었습니다. 
- 주말이나 긴 연휴가 겹치거나, 개별 종목이 수일간 거래 정지가 된 경우, 캘린더 시간이 경과함에 따라 필수적으로 보존되어야 할 '실제 거래일'의 데이터마저 무의미하게 삭제되어 데이터 소실(Data Loss)이 발생하는 문제가 있었습니다.
- 1GB RAM 환경에서는 파이썬에서 종목별로 순회(For-loop)하며 삭제하는 것은 DB 락(Lock)을 유발하므로 다시 돌아갈 수 없었습니다.

## Decision
다음과 같은 2단계 지능형 GC(Intelligent GC) 아키텍처를 도입하여 새벽 4시(`04:00`)에 실행합니다.

1. **스마트 트리거 (Smart Trigger)**: 
   - 파이썬 스케줄러가 구동되면 DB를 한 번 조회하여 "어제(전날) 날짜의 데이터가 단 1건이라도 존재하는지" 판별합니다.
   - 전날이 휴장일(주말/공휴일)이라 데이터가 없다면, GC를 완전히 스킵하여 불필요한 삭제를 막습니다.
2. **개별 거래일 기준 임시 테이블 삭제 (Hash Join Pattern)**:
   - 파이썬 For-loop를 배제하고, SQLite의 임시 테이블(`TEMP TABLE`)과 윈도우 함수(`DENSE_RANK()`, `ROW_NUMBER()`)를 사용합니다.
   - 단 하나의 SQL 트랜잭션으로 각 종목별 최신 N영업일(분봉 2일, 일봉 500일) 임계치를 O(N)으로 계산한 뒤 일괄 삭제합니다.

## Alternatives Considered

### 종목별 캔들 개수(Row-count) 기준 분할 삭제 (For-loop Chunking)
- **Pros**: 개별 종목의 상태를 가장 정확히 파악하여 삭제할 수 있음.
- **Cons**: 파이썬에서 2,400번의 `DELETE` 쿼리를 쏘면 SQLite 파일 락과 트랜잭션 오버헤드가 극심함.
- **Rejected**: 임시 테이블 기반 해시 조인 기법으로 대체하여 단 1~2회의 쿼리로 동일한 효과를 내도록 했습니다.

## Consequences
- **무결성 보장**: 거래 정지 종목이든 주말이든 상관없이, 개별 종목의 '실제 거래일' 캔들만 정확하게 보존됩니다.
- **성능 최적화**: O(N^2)로 느려지는 상호연관 서브쿼리(Correlated Subquery)나 파이썬 루프를 피하고, 인메모리 임시 테이블을 통한 인덱스 탐색(O(N))으로 삭제 속도가 초단위로 단축되었습니다.
- **안정성**: 스케줄러 구동 시간이 자정 근처(`23:00`)에서 사용자 및 타 스케줄러 간섭이 없는 `04:00`으로 이동하여 DB 락을 완벽히 회피합니다.
