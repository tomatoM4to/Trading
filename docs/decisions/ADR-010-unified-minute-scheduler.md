# ADR-010: Unified Minute OHLCV Scheduler (Self-Healing Architecture)

## Status
Accepted | Supersedes ADR-001

## Date
2026-07-24

## Context
기존 `ADR-001`에서 채택한 분봉 스케줄러 아키텍처는 과거 데이터를 복구하는 백필(Backfill) 작업과 실시간 장중 폴링(Polling) 작업이 물리적으로 분리되어 있었습니다. 
하지만 이로 인해 다음과 같은 치명적인 문제(Edge Cases)들이 발생했습니다.

1. **Midnight Bug (Empty DataFrame 처리 불가)**: 장이 닫힌 야간(예: 새벽 1시)이나 휴일에 서버를 기동할 경우, KIS API가 `09:00` 이전이라는 이유로 빈 데이터(`df.empty`)를 반환합니다. 기존 코드는 이를 '모든 데이터를 수집했다'고 오해하고 `break` 해버려, 정작 필요한 이전 영업일의 과거 데이터를 복구하지 못했습니다.
2. **야간 스케줄러 Lock 현상**: 15:55분이 넘으면 스케줄러가 즉시 종료되도록 최상단에 조건문이 걸려 있어, 장 마감 후 야간에 서버를 배포/재시작하면 백필조차 수행되지 못한 채 다음 날 아침까지 스케줄러가 죽어있는 현상이 발생했습니다.
3. **코드 복잡도**: 백필 큐와 실시간 큐가 분리되어 있어 예외 처리 로직이 파편화되었습니다.

## Decision
기존의 분리된 백필(`run_minute_backfill_task`)을 완전히 제거하고, 모든 상황을 커버할 수 있는 **'단일 통합 분봉 스케줄러(Unified Overlap-Aware Scheduler)'** 구조로 재설계했습니다.

1. **Empty Fallback (빈 데이터 자가 치유)**
   - KIS API가 `df.empty`를 반환할 때 종료(`break`)하지 않고, 날짜를 '하루 전'으로 빼고 시간을 전날 장 마감 시간인 `15:30:00`으로 강제 세팅한 뒤 루프를 이어갑니다(`continue`).
   - 이를 통해 야간 부팅, 주말, 연휴, 신규 상장일 등의 빈 틈(Gap)을 스스로 징검다리 건너듯 극복(Self-Healing)합니다.

2. **Overlap-Aware Early Exit (중복 감지 조기 종료)**
   - 스케줄러는 기본적으로 최대 15회(약 3영업일)의 과거 탐색 루프를 돕니다.
   - 단, API에서 새로 가져온 분봉들의 가장 과거 시간이 DB에 이미 존재하는 최신 시간(`last_datetime`)과 단 1초라도 겹치면(Overlap), 💡"필요한 갭을 다 채웠다"고 판단하고 필요한 데이터만 인서트한 뒤 즉시 루프를 탈출(`break`)합니다.
   - 실시간 장중에는 첫 페이지(120개)만 가져와도 과거와 100% 겹치므로 단 1스텝 만에 초고속으로 종료됩니다.

3. **Night-time Lifecycle (야간 무한루프 1사이클 보장)**
   - 15:55 이후 즉각 셧다운되는 Lock을 루프의 '최하단'으로 이동시켰습니다.
   - 야간에 서버를 켜더라도 큐에 쌓인 전 종목을 무조건 1사이클 완주(과거 빈 데이터 완벽 복구)한 뒤에야 내일 아침을 기약하며 종료됩니다.

4. **API Priority Override (우선순위 새치기)**
   - 관리자 검증 엔드포인트(`/admin/...`)나 사용자가 즉시 갭필(Gap-fill)을 요구할 경우, 스케줄러의 기본 우선순위(Priority 7) 대신 `priority=2`를 주입하여 큐의 맨 앞단에서 초고속으로 처리될 수 있도록 개선했습니다.

## Alternatives Considered

### 유지보수 관점에서의 예외 처리 분기 (if-else 추가)
- Pros: 기존 백필 코드를 살리면서 야간 시간대(`time < 09:00`) 분기문만 추가하면 당장 동작은 함.
- Cons: 휴일, 연휴, 특정 종목의 거래정지 등 다양한 엣지 케이스를 모두 `if-else`로 하드코딩해야 하므로 복잡도가 기하급수적으로 증가.
- Rejected: 하드코딩 대신 `df.empty` 시 날짜를 하루 빼는 단 4줄의 Fallback 로직만으로 모든 엣지 케이스를 동적으로 돌파하는 수학적 해법을 선택함.

## Consequences
- 코드베이스에서 잉여 백필 로직이 완전히 사라져 유지보수가 극도로 단순화되었습니다.
- 서버를 언제 켜든(낮, 밤, 주말) 개발자가 신경 쓸 필요 없이 봇이 알아서 완벽한 무결성(100% Match)으로 데이터를 복구합니다.
- `ADR-001`을 완전히 대체하며, Oracle Cloud 1GB RAM 환경에서도 단일 큐로 안정적인 Zero-Latency 지향 아키텍처를 완성했습니다.
