# ADR-021: SQLite Push-down 쿼리를 위한 파라미터 엄격 검증 (Strict Input Validation)

## Status
Accepted

## Date
2026-08-04

## Context
본 프로젝트의 스크리너 엔진은 이동평균선 정배열 및 크로스와 같은 복잡한 기술적 지표 연산을 윈도우 함수를 사용하여 SQLite 내부로 위임(Push-down)하는 방식을 핵심으로 합니다. 

최근 벤치마크 테스트 과정에서, 클라이언트나 스크립트로부터 잘못된 파라미터(예: `direction: "up"`, 원래 기대값은 `"golden"` 또는 `"dead"`)가 전달되었을 때 백엔드 로직이 이를 에러로 처리하지 않고 조용히 SQL 쿼리의 WHERE 절 마지막에 `AND 1=0` 이라는 더미 조건을 붙여버리는 문제가 발견되었습니다.

SQLite의 강력한 쿼리 옵티마이저(Query Optimizer)는 `1=0`이 항상 거짓(False)이라는 것을 즉시 인식하고, 무거운 CTE 연산(테이블 풀 스캔 및 윈도우 함수 계산 등)을 아예 수행하지 않은 채(Short-circuit) 0.03초 만에 빈 결과를 반환했습니다. 

이러한 현상은 표면적으로는 API가 매우 빠르게 응답하는 것처럼 보이나, 실제로는 잘못된 파라미터 유입이라는 버그를 완전히 은폐(Masking)하여 벤치마크 결과를 왜곡하고, 향후 프론트엔드에서 오작동이 발생하더라도 디버깅을 극도로 어렵게 만드는 치명적인 위험을 내포하고 있습니다.

## Decision
스크리너 엔진으로 전달되는 모든 파라미터에 대해, SQL 쿼리 문자열 조립이 시작되기 전 **엄격한 파라미터 검증(Strict Input Validation)**을 강제합니다.

기대하지 않은 값이나 필수 값이 누락된 파라미터가 유입될 경우, 조용히 `1=0`과 같은 더미 조건으로 우회하지 않고 즉각적으로 `ValueError`를 발생시켜야 합니다. (이는 FastAPI의 예외 처리기를 통해 클라이언트에게 HTTP 400 Bad Request 에러로 명확히 전달됩니다.)

## Consequences
- **Positive:** 프론트엔드나 벤치마크 스크립트에서 잘못된 파라미터를 전송할 경우 즉각적으로 400 에러를 받게 되므로 문제 원인 파악과 디버깅이 매우 쉬워집니다.
- **Positive:** SQLite 쿼리 옵티마이저의 의도치 않은 숏서킷(Short-circuit)이 방지되어, 벤치마크 테스트 시 실제 쿼리 실행 부하와 소요 시간이 정확하게 측정됩니다.
- **Negative:** 필터 핸들러(`screener_service.py`) 작성 시 모든 파라미터에 대해 명시적인 유효성 검사 로직(Boilerplate)을 추가해야 하므로 코드 길이가 다소 증가합니다.
