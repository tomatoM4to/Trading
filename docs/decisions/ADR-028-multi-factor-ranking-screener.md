# ADR-028: Multi-Factor Ranking Screener

## Status
Accepted

## Date
2026-08-10

## Context
기존 스크리너 엔진은 개별 필터 로직이 종목의 통과 여부만을 판단하여 집합(`Set[str]`) 형태로 반환하는 구조였습니다. 이러한 '통과/탈락(True/False)' 방식은 다중 조건 교집합 시 조건에 간신히 턱걸이한 종목과 완벽히 부합하는 종목을 구별할 수 없는 한계가 있었습니다. 트레이더들은 여러 조건이 동시에 적용될 때 "각 지표별로 가장 우수한 폼을 보여주는 종목"을 점수나 순위로 비교하고 싶어 합니다. 따라서 1GB RAM 제약을 유지하면서도 다중 지표의 랭킹을 매길 수 있는 구조적 변화가 필요했습니다.

## Decision
1. **Float 지표 값 추출**: 모든 스크리너 필터 핸들러가 단순 `Set` 대신 딕셔너리(`Dict[str, Dict[str, float]]`)를 반환하도록 변경합니다. `{'ticker': {'filter_id': value}}` 형태로 통과한 종목들의 구체적 조건 부합 강도(Float)를 반환합니다.
2. **In-Memory 병합(Merge) 파이프라인**: 스크리너 엔진의 파이프라인(AND/OR 체인)에서 체인 간의 결과를 교합할 때, 파이썬 내장 딕셔너리 연산자(`|`)를 사용하여 지표 값들을 하나의 객체로 누적 병합합니다.
3. **지표별 정렬 기준 확립**: 
   - 이평선 정배열(`ma_alignment`): 이격도 편차율 (값이 작을수록 응집도가 높아 우수함 -> 오름차순 권장)
   - 이평선 교차(`ma_cross`): 교차 시점의 단기선과 장기선의 이격 차이 폭 (값이 클수록 모멘텀이 강함 -> 내림차순 권장)
   - 이평선 수렴(`ma_convergence_consolidation`, `point`): 밴드폭 오차율 (값이 작을수록 밀집도가 완벽함 -> 오름차순 권장)
   - 수급 랭킹(`foreign_net_buy_rank`, `inst_net_buy_rank`): 순위 내 통과가 목적이므로 부가 수치 제공 없이 `0.0` 일괄 부여.
4. **프론트엔드 정렬 위임 (Late Sorting)**: 백엔드 서버는 무거운 정렬 로직이나 복잡한 가중치 합산을 수행하지 않고, 추출된 `filter_values` 팩터 묶음을 클라이언트로 그대로 전달(SSE)하여 사용자 UI가 동적 정렬을 책임지도록 역할을 분리합니다.

## Consequences
- **장점**: 트레이더가 프론트엔드에서 다중 팩터를 기반으로 종목을 직관적으로 정렬하고 우량주를 직접 비교할 수 있어 필터 결과의 질이 비약적으로 상승합니다.
- **장점**: Pandas DataFrame과 같은 무거운 분석 객체를 배제하고 파이썬 기본 딕셔너리(`Dict`) 병합을 사용하므로 1GB RAM 환경에서도 성능 저하(OOM)나 오버헤드가 발생하지 않습니다.
- **단점**: SSE 스트림 응답 시 `filter_values` Payload가 추가되어 패킷 용량이 소폭 증가합니다.
- **영향**: 프론트엔드는 응답받은 `filter_values`를 해석하여 사용자가 원하는 최우선 지표를 기준으로 동적 그리드 정렬(Client-Side Sorting)을 구현해야 합니다.
