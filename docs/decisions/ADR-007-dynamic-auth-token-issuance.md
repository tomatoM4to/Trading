# ADR-007: 환경 변수(DEBUG) 기반의 KIS 인증 토큰 동적 발급 전략

## Status
Accepted

## Date
2026-07-14

## Context
KIS OpenAPI는 접속 인증을 위해 OAuth 토큰(접근 토큰, Access Token)을 사용한다.
기존 아키텍처에서는 중앙 `SystemScheduler`가 서버 부팅 시점에 즉각적인 인증 상태를 보장하기 위해 `refresh_auth_job(force=True)`를 강제로 수행했다.
그러나 다음과 같은 문제점과 개선 요구사항이 대두되었다:

1. **로직의 단절**: 스케줄러 내부에서 `force=True` 옵션을 주입하더라도, 실제 `asyncio.to_thread(auth)` 호출 시 이 인자가 넘어가고 있지 않아 토큰의 강제 발급이 원활하게 동작하지 않는 버그가 있었다.
2. **개발 환경(Local)에서의 API 낭비**: 로컬에서 코드를 수정할 때마다 Uvicorn이 핫 리로드(Hot Reload) 되는데, 매번 무조건 `force=True`로 인증을 태우면 일일 인증 API 호출 한도를 빠르게 소진할 우려가 있다.
3. **운영 환경(Prod)에서의 신뢰성**: 반면 실제 운영 서버가 재시작(도커 배포 등) 될 때는 캐시 된 낡은 토큰을 믿는 것보다, 안전하게 가장 신선한 토큰으로 새로 발급받는 것이 시스템 안정성에 유리하다.

## Decision
서버 부트스트랩 단계의 KIS 인증 토큰 발급 로직을 `.env`의 `DEBUG` 환경 변수와 동기화(Sync)하는 방식으로 개편한다.

- `DEBUG=True` (로컬 개발): `force=False` 로 작동하여 기존 캐시된 토큰이 유효하다면 그대로 재사용한다.
- `DEBUG=False` (실전 운영): `force=True` 로 작동하여 기존 캐시를 완전히 무시하고 KIS API 통신을 통해 신규 토큰을 강제 발급받는다.
- 또한 `scheduler.py`의 `refresh_auth_job`이 내부 `auth()` 함수 호출 시 `force` 파라미터를 정확하게 매핑하도록 인터페이스를 수정했다 (`await asyncio.to_thread(auth, force=force)`).

## Alternatives Considered

### 1. 전역적으로 항상 force=False 사용
- **장점**: 개발이든 운영이든 토큰 캐싱을 최대한 활용하여 API 부하를 줄임.
- **단점**: 실전 운영 서버가 예기치 않게 재부팅되었을 때 만료 시간이 아슬아슬하게 남은 토큰을 물고 올라갔다가, 장중에 인증 에러가 발생할 치명적 위험이 존재함.
- **결과**: 기각. 배포 직후에는 항상 토큰의 유효기간(24시간)을 최대로 확보해야 한다.

## Consequences
- 로컬 개발 시 잦은 서버 재시작에도 토큰 발급 한도 고갈을 걱정할 필요가 없어졌다.
- 운영 서버에 `main` 브랜치를 배포할 때마다, 어차피 도커 컨테이너가 새로 뜨면서 깨끗하게 새 토큰을 갱신해주므로 장중(`09:00~15:30`) 토큰 만료의 위험(Risk)이 원천 차단된다.
- 이를 통해 개발자 경험(DX)과 운영 서버의 신뢰성 두 마리 토끼를 잡았다.
