# ADR-002: Daily OHLCV Scheduler and Smart Gap-Fill

## Status
Accepted

## Date
2026-07-12

## Context
일봉(`daily_ohlcv`) 데이터를 수집할 때 두 가지 상황을 모두 지원해야 합니다.
1. **서버 최초 구동 (Cold Start)**: DB가 완전히 비어있을 때 최소 500일치의 캔들을 2,400개 전 종목에 걸쳐 수집해야 함.
2. **장기간 서버 중지 후 재가동 (Gap Fill)**: 예를 들어 1달간 서버가 꺼져있었다면, 마지막 수집 날짜부터 오늘까지의 빈 구간만 똑똑하게 채워야 함.
3. **정규 업데이트 (Daily Cron)**: 매일 장 마감 후(16:00) 단 하루치 데이터만 가볍게 수집해야 함.

## Decision
위 세 가지 유스케이스를 **단일 로직(Dual Execution Process)**으로 통합하여 해결합니다.

1. **스마트 백필(Gap-fill) 메커니즘**:
   - 워커는 항상 DB의 `MAX(date)`(가장 최신 수집일)를 메모리에 맵핑한 뒤 KIS API를 호출합니다.
   - KIS API가 반환한 과거 일봉 리스트 중, `MAX(date)`와 같거나 더 과거인 날짜를 마주치면 즉시 `break` 하여 과거 역추적을 중지합니다.
   - 이로 인해 1달이 비어있으면 자동으로 1달 치를 수집하고 멈추며, 어제까지 채워져 있으면 오늘 하루치만 수집하고 멈춥니다.
2. **부트스트랩 강제 통합**:
   - `main.py`의 `lifespan` 훅을 통해 서버가 부팅될 때, `daily_ohlcv` 데이터 존재 여부와 무관하게 무조건 스케줄러(`run_daily_ohlcv_scheduler`)를 1회 호출합니다.
   - 이를 통해 Cold Start 시에는 500일치를, 서버 재시작 시에는 자동으로 Gap Fill을 수행합니다.
3. **16:00 정규 배치**:
   - `SystemScheduler`에 오후 4시 크론잡(Cron Job)을 등록하여 부트스트랩과 동일한 스케줄러 함수를 호출합니다. 

## Alternatives Considered
- **빈 DB인지 확인하는 if 문으로 콜드스타트 전용 로직 분리**:
  - Pros: 명시적임.
  - Cons: 코드가 중복되며, 1달간 꺼져있었을 때(DB는 비어있지 않음)의 복원 로직을 따로 짜야 함.
  - Rejected: `MAX(date)` 기반 역추적 로직 하나로 모든 케이스(콜드스타트, 갭필, 일일업데이트)가 유려하게 커버되므로 단일 함수 재사용을 선택.

## Consequences
- 서버를 언제 켜고 끄더라도, 운영자의 수동 복원 작업 없이 무결한 일봉 시계열 데이터가 자동으로 보장됩니다.
- 1GB 메모리 환경에서 불필요한 과거 데이터 조회(Over-fetching)를 0으로 만들어 KIS API의 Rate Limit을 완벽하게 방어합니다.
- (향후 계획) 11:00 PM 경 500일 초과 데이터를 지우는 GC 로직을 추가하여 DB 비대화를 방어할 예정입니다.
