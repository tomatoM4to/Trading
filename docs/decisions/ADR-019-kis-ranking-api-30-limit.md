# ADR-019: KIS Ranking API 30-Item Hard Limit Strategy

## Status
Accepted

## Date
2026-08-03

## Context
스크리너 파이프라인에 수급(세력) 지표를 도입하기 위해, 외국인 및 기관 순매수 상위 종목을 필터링하는 로직을 추가하기로 결정했습니다.
초기 설계에서는 사용자에게 상위 30개 또는 60개를 선택(Limit)할 수 있는 옵션을 제공하고, KIS OpenAPI의 연속조회(`tr_cont`) 기능을 사용하여 데이터를 2회 Fetch하는 방식(Pagination)을 계획했습니다.
하지만 실제 KIS 오픈API의 '국내기관_외국인 매매종목가집계'(`FHPTJ04400000`) 엔드포인트는 HTS [0440] 화면과 동일하게 상위 30건 고정 반환 정책을 취하고 있으며, `tr_cont` 헤더를 내려주지 않아(연속조회 미지원) 30개 이상의 데이터를 가져올 수 없다는 한계가 발견되었습니다.

## Decision
1. **API Limit 고정 수용**: '외국인 순매수 상위 랭킹(`foreign_net_buy_rank`)'과 '기관 순매수 상위 랭킹(`inst_net_buy_rank`)' 필터는 백엔드에서 무조건 **상위 30개**만 반환하도록 하드코딩(Hard Limit)합니다.
2. **연속조회(Pagination) 로직 제거**: 작동하지 않는 무의미한 연속조회(Dead Code)를 백엔드에서 완전히 제거하여 기술 부채를 방지합니다.
3. **프론트엔드 UI 단순화**: 사용자에게 불가능한 옵션(상위 60개 선택)을 제공하지 않고, 대신 UI에서 해당 필터를 선택 시 `(KIS 정책상 상위 30개 고정 반환)`이라는 안내 텍스트를 노출하여 혼동을 방지합니다.

## Alternatives Considered

### 종목별 수급 API 반복 호출 (investor_trade_by_stock_daily)
- Pros: 정확히 원하는 N개의 종목에 대해 수급을 조회할 수 있음.
- Cons: 2,400개 전 종목을 루프 돌며 조회해야 하므로 1초에 20건 통신 제한(Rate Limit)이 있는 KIS 환경에서는 스크리너 응답에 수 분이 소요됨. Zero-Latency 원칙에 심각하게 위배됨.
- Rejected: 실시간 스크리너 엔진의 철학과 맞지 않음.

## Consequences
- 수급 기반 스크리닝 시 모수가 최대 30개로 고정되므로, 다른 조건(이평선 정배열 등)과 `AND` 교집합 연산을 수행할 때 최종 결과가 매우 적게(또는 0개) 나올 수 있습니다. 트레이더(사용자)는 이 제약을 인지하고 스크리너를 조합해야 합니다.
- 불필요한 네트워크 통신 횟수가 줄어들어 스크리너 파이프라인의 속도는 더욱 향상됩니다.
- 향후 KIS API 외의 서드파티 벤더나 자체 DB 구축을 통해 수급 데이터를 확보하지 않는 이상, 랭킹 API는 HTS 기준(30건) 제약을 벗어날 수 없습니다.
