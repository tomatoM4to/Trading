# ADR-011: Perfect Time Synchronization for Chart Indicators

## Status
Accepted

## Date
2026-07-26

## Context
Trading Server 프로젝트에 Next.js 기반의 프론트엔드가 도입되면서 Lightweight Charts를 이용해 분봉(1~60m) 및 일봉(1D/1W/1M) 차트를 구현했습니다. 
차트 렌더링 과정에서 다음과 같은 치명적인 버그가 발견되었습니다:
- 사용자가 30분봉 차트 등 큰 타임프레임을 볼 때, 캔들(CandlestickSeries)은 30분 단위로 정렬되어 그려졌으나 이동평균선(LineSeries)은 1분 단위 원본 데이터가 모두 주입되었습니다.
- Lightweight Charts의 X축(Time Scale)은 입력된 모든 시리즈의 Time 값을 기준으로 생성되기 때문에, 캔들에 존재하지 않는 1분 단위의 빈 시간들이 X축에 생성되었습니다.
- 결과적으로 캔들 데이터가 끝난 이후에도 이평선만이 1분 단위로 차트의 빈 공간(미래 시간대)으로 길게 뻗어나가며, X축에 00:05, 00:10 등 현지 타임존 기준 다음 날 아침 시간대가 표시되는 버그가 발생했습니다.

이 문제를 해결하기 위해 프론트엔드 레벨에서 이동평균선을 처리하는 방식에 대한 설계 결정을 내려야 했습니다.

## Decision
**이동평균선 데이터를 캔들과 완벽하게 동일한 시간축(Time)으로 그룹화(Aggregation)하여 제공하는 'Perfect Time Synchronization' 방식을 채택합니다.**

## Alternatives Considered

### 1. Context-Aware Visibility (단순화)
- **개념**: 1D, 1W 등 일봉 이상의 타임프레임으로 전환할 경우, 분봉 기준의 이평선(1m, 3m 등) 버튼을 모두 비활성화(Disabled)하고 차트에서 숨기는 방식입니다.
- **Pros**: 구현이 극도로 단순하며 코드가 간결해집니다.
- **Cons**: 사용자가 일봉에서 단기선의 상대적 위치를 보고 싶어 하는 요구(할 수 있지만 끄는 것)를 원천 차단하여 사용자 경험이 하락합니다.
- **Rejected**: 자유도 제한으로 인한 플랫폼 완성도 저하 우려 때문에 거부되었습니다.

### 2. Time-Scale Ignore
- **개념**: Lightweight Charts의 `timeVisible: false` 옵션이나 Tick 생성을 강제로 조작하여 보이지 않게 처리하는 방식입니다.
- **Pros**: 데이터 가공 로직 추가 불필요.
- **Cons**: 차트 라이브러리의 설계 철학을 거스르는 해킹이며, 툴팁 표시나 마우스 커서 스냅핑 시 여전히 빈 시간대에 포커스되는 등 사이드 이펙트가 많습니다.
- **Rejected**: UI 버그 발생 우려로 거부되었습니다.

## Consequences
- `chart-utils.ts` 내의 `extractLineSeriesData` 함수가 현재 선택된 `timeframe` 정보를 주입받도록 시그니처가 변경되었습니다.
- 이평선 데이터도 캔들 그룹핑과 완벽하게 일치하는 알고리즘(예: 30분봉은 매 30분 단위 내림 연산, 주봉은 월요일 기준 연산)을 통해 시간축이 재생성됩니다.
- 각 시간 구간별로 **가장 마지막 유효한 이평선 값** 하나만을 샘플링하여 캔들의 종가 위치와 정확히 매칭시킵니다.
- 백엔드는 기존 API(일봉 전체 혹은 분봉+일봉 CTE 매핑 쿼리)를 그대로 유지하며, 프론트엔드의 메모리와 브라우저 연산 능력만을 활용하여 클라이언트 사이드 애그리게이션(Client-Side Aggregation)을 수행함으로써 1GB RAM 백엔드 서버의 과부하를 방지합니다.
