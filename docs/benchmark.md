# 스크리너 벤치마크

## 현재 판단

벤치마크는 **스크리너 HTTP 요청부터 SSE 완료까지의 관측 시간**이다. 엔진 내부 연산 시간만을 분리한 측정이나 동시 사용자 부하 테스트가 아니다. 결과를 볼 때는 시간보다 먼저 시나리오 버전, 서버/로컬 구분, 완료 판정 방식을 확인한다.

- **main에서 실행 가능한 하네스:** 기존 5 Light + 5 Heavy, 총 10개 시나리오다.
- **dev에 보존된 개선 하네스:** 7 Light + 5 Heavy, 총 12개 시나리오다. SSE 오류·미완료를 실패로 처리하며 별도 계약 테스트가 있다. 이번 문서 정리로 main에 이식한 것은 아니다.
- **가장 최근 보존 결과:** dev의 2026-08-22 12:18 결과다. 12개 행 모두 `Success`로 기록됐지만, 이 문서 작업에서 서버 실행이나 성능을 재검증하지 않았다.
- **성능 비교 경계:** 기존 Heavy는 랭킹/AND에 의한 후보 축소가 가능하고, 개선 Heavy는 독립 전체 후보 스캔과 OR 조합이다. 번호가 같아도 서로 다른 작업이므로 개선율을 계산하지 않는다.

현재 저장 계층은 디스크 OHLCV 정본 + MA 전용 Shared In-Memory SQLite다. 과거의 전체 인메모리 설명을 현재 구조로 읽지 않는다. 자세한 내용은 [DB와 메모리 모델](database.md)을 따른다.

## 이번 정리의 범위

기준은 main `652bb24da07e35c07539997d9faa10413a414eba`와 dev `b8e94dd88064fee47895362b736d49c0cd4b4cf2`다. 기존 CSV는 경로와 내용을 유지했다. dev에만 있는 CSV·스크립트·테스트는 커밋 고정 링크로 연결했다. 브랜치를 삭제하거나 이동해도 출처를 식별할 수 있도록 브랜치명만으로 연결하지 않는다.

이 문서에서 **확인**은 저장된 파일 또는 구현을 대조했다는 뜻이다. **기록상**은 당시 문서의 환경·목적 설명을 인용한다는 뜻이며, **미검증**은 이번에 측정하거나 재현하지 않은 항목이다. 저장된 `Success`는 그 실행기의 판정 문자열이며 데이터 정답성이나 서비스 가용성 보장이 아니다.

## 다음 검증에서 남길 것

1. 서버 코드와 하네스의 정확한 커밋, 전체 요청 payload 또는 그 해시.
2. 측정 대상 환경, DB 스냅샷·행 수·최신 캔들 시각, MA 준비 상태.
3. 반복 횟수와 워밍업 정책, 각각의 원시 결과 및 중앙값·분위수.
4. SSE 완료/오류 근거, 메모리 RSS·스왑·I/O를 주장하려면 해당 계측 로그.

운영 서버에 부하를 주는 실행은 별도 작업으로 다룬다. 문서 정리만으로 기존 운영 주소에 측정을 실행하지 않는다.
