# [Idea] 원자적 이평선 스크리너 아키텍처 (Atomic MA Filters)

## Problem Statement
제어공학 출신 트레이더가 백엔드 DB 연산에 무리를 주지 않으면서도, 단순하고 명확한 논리 블록(AND/OR)을 조합해 정배열 상태 유지 및 돌파(Cross) 시점을 정교하게 타겟팅할 수 있는 스크리너 구조를 어떻게 만들 것인가?

## Recommended Direction
**상태(State)와 이벤트(Event)의 철저한 분리 및 원자화 (Atomic Filters)**

무거운 하나의 '슈퍼 필터'를 만드는 대신, 단일 목적만 수행하는 아주 가벼운 필터들을 제공하여 사용자가 제어 로직처럼 레고 블록을 조립(AND/OR)하도록 설계합니다. 백엔드 SQL 제네레이터는 극도로 단순화되며, SQLite는 인덱스를 효율적으로 활용할 수 있습니다.

1. **상태 필터 (`ma_alignment`)**: 파라미터로 `lines: [5, 20, 60]`, `duration: 3`을 받습니다.
   - 백엔드는 이를 `(MA5 > MA20) AND (MA20 > MA60)` 조건이 최근 3일간 유지되었는지를 체크하는 윈도우 쿼리로 변환합니다.
2. **이벤트 필터 (`ma_cross`)**: 파라미터로 `short: 5, long: 20, direction: "golden"`을 받습니다.
   - 어제는 `MA5 <= MA20`이었으나 오늘은 `MA5 > MA20`인 종목만 빠르게 추출합니다.

트레이더는 프론트엔드에서 `(MA Alignment AND MA Cross AND 기관순매수 Top30)` 형태로 무한한 논리를 전개합니다.

## Key Assumptions to Validate
- **동적 윈도우 함수 성능**: `duration`(유지 기간) 처리를 위한 SQLite 윈도우 함수(`LAG` 혹은 윈도우 `MIN()`)가 2,400개 종목에 대해 1GB RAM 환경에서 OOM 없이 즉시 응답하는지 검증이 필요합니다.

## MVP Scope (최소 구현 범위)
- `ma_alignment` 필터: 배열로 들어온 N개의 이평선이 크기순으로 정렬되었는지(정배열/역배열) 판별하는 동적 SQL 제네레이터 작성.
- `ma_cross` 필터: 2개의 이평선 교차점 판별 SQL 작성.
- 위 필터들이 기존 스크리너 엔진의 `Set-Theory` (집합론 교집합 `&`, 합집합 `|`) 아키텍처에 완벽히 연동되도록 파이프라인 구성.
- **파라미터 유효성 검사 (Dynamic Duration Limits)**: GC 삭제 주기와 충돌하지 않도록 사용자 요청 파라미터 기반 이론상 최대치 한계 방어 로직 추가.
  - **일봉 (Daily)**: 300 달력일(약 200 영업일) 보관. `duration <= 200 - max(lines)`
  - **분봉 (Minute)**: 7 달력일(5 영업일, 1950 캔들) 보관. `duration <= 1950 - max(lines)`

## Not Doing (and Why)
- **이격도(Divergence) 필터 백엔드 연산**: 연산이 너무 무거워 SQLite에 치명적이므로 백엔드 연산에서는 탈락. 교집합이 끝난 소수의 최종 종목에 한해서만 프론트엔드(클라이언트) 단으로 빼서 계산 및 시각화 수행.
- **가중치 합산 / 점수제 (Scoring System)**: 조건별 점수를 부여해 합산하는 방식은 DB 쿼리를 무겁게 하고 집합론 최적화를 원천 무력화하므로 탈락. 철저한 Boolean(True/False) 논리 조합만 허용.
- **상태와 이벤트 혼합 쿼리**: 하나의 필터 API 안에서 정배열 N일 유지와 골든크로스 시점 탐색을 섞지 않음. (복잡도 증가 방지)
