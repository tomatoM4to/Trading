# 📄 [아이디어 원페이지] In-Memory 휘발성 이평선(MA) 전용 아키텍처

## Problem Statement (해결하고자 하는 문제)
기존의 돌파(Breakout) 스크리너 엔진은 1GB RAM 환경에서 데이터를 보호하기 위해 디스크 DB의 원본 OHLCV 데이터를 대상으로 SQLite 윈도우 함수를 태워 동적으로 이평선(MA)을 계산했습니다. 하지만 이 방식은 쿼리가 무거워 60초 타임아웃 병목을 유발하며, RAM 점유율도 70%에 달하는 불안정성을 보였습니다.

"어떻게 하면 커스텀 이평선의 유연성을 포기하는 대신, 디스크 I/O를 원천 차단하고 스크리너 쿼리를 O(1) 수준의 단순 비교 연산으로 만들어 지연 시간(Latency)을 획기적으로 줄일 수 있을까?"

## Recommended Direction (권장 방향)
**역할의 완벽한 분리: 디스크 DB(OHLCV 영구 보존) vs 인메모리 DB(휘발성 MA 전용)**
이평선(MA) 데이터를 디스크에 절대 저장하지 않고, 오직 인메모리 DB에서만 생성/유지/폐기하는 휘발성(Transient) 생명주기를 갖게 합니다.

1. **디스크 영구 저장 (`trading.db`)**: 
   - 원본 캔들 테이블(`daily_ohlcv`, `minute_ohlcv`)만 저장. 이평선 테이블은 아예 존재하지 않음.
2. **08:00 Daily Reset & Bootstrapping (리빌드)**: 
   - 매일 장 시작 전(08:00) 또는 콜드 스타트 시, 인메모리 DB의 MA 테이블을 싹 비웁니다(DROP).
   - 디스크 DB에서 일봉 전체(300일)와 분봉 최근 2일치의 OHLCV를 읽어와, 백그라운드에서 고정 이평선(5, 10, 20, 60, 120, 200)을 일괄 계산하여 인메모리 DB(`daily_ma`, `minute_ma`)에 적재합니다.
3. **장중 실시간 스케줄러 (09:00~15:30)**: 
   - 스케줄러가 파이썬으로 최신 분봉의 이평선을 계산한 뒤, **인메모리 DB에만 INSERT** 합니다. (장중 디스크 I/O 완벽 제거)
   - 장이 마감되면 인메모리의 분봉 MA는 딱 3일치 누적분이 되며, 다음 날 아침 08:00 리빌드 때 자연스럽게 GC(Garbage Collection)가 완료됩니다.

## Key Assumptions Validated (검증된 가설)
- **메모리 안정성**: 분봉 MA 3일치 전체(약 280MB)와 일봉 MA 전체(약 72MB)를 인메모리에 모두 올려도 총 350MB 안팎으로, 1GB RAM 환경에서 완벽히 방어됩니다.
- **소외주 디스크 I/O 방어**: 거래량이 적어 캔들이 부족한 소외주라 할지라도, 스크리너가 '오늘치' 뿐만 아니라 '3일치 전체' 분봉을 인메모리에서 즉각 스캔할 수 있으므로 절대 디스크로 Fallback하지 않습니다.

## MVP Scope (최소 기능 구현 범위)
- **이평선 스펙 확정**: 일/분봉 공통 6개 고정 컬럼(`ma5`, `ma10`, `ma20`, `ma60`, `ma120`, `ma200`). 커스텀 이평선(예: 33일선 등) 지원 제거.
- **스키마 재설계**: 인메모리 전용 `daily_ma`, `minute_ma` 테이블 설계. (디스크 DB 스키마에는 추가하지 않음)
- **부트스트랩 및 08:00 스케줄러 구현**: 디스크에서 최근 N일치 OHLCV를 읽어와 인메모리 MA 테이블을 리빌드하는 파이프라인.
- **스크리너 쿼리 개편**: 윈도우 함수(Push-down) 로직을 모두 걷어내고, 인메모리 `ma` 테이블 직접 단순 조건(>, <) 조회로 롤백.
- **실시간 스케줄러 개편**: 장중 스케줄러는 순수 파이썬으로 최신 MA를 계산해 인메모리에만 INSERT 수행.

## Not Doing (우리가 하지 않을 것과 그 이유)
- **디스크 DB에 이평선(MA) 데이터 저장(Sync)**: 인메모리 비대화 문제(GC)와 디스크 쓰기 오버헤드를 한 번에 해결하기 위해, MA 데이터는 매일 아침 재계산되는 휘발성 데이터로만 취급합니다.
- **스크리너 내부의 디스크 DB 조인(Fallback)**: 속도를 지연시키는 디스크 I/O를 원천 차단합니다. 클라이언트가 3일을 초과하는 분봉 조건을 요구하면 정책적으로 에러를 반환합니다.
