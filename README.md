# Trading Server

KIS OpenAPI를 활용한 Zero-Latency Breakout(돌파) 전략 기반의 자동 매매 백엔드 시스템입니다.
Oracle Cloud Free Tier(1 OCPU / 1GB RAM)의 자원 제약을 극복하기 위해 SQLite WAL 모드와 고도의 백그라운드 스케줄러 최적화 기법을 적용했습니다.

---

## 전략 스크리너 사용 가이드

스크리너는 여러 기술적 조건과 투자자 순매수 순위를 조합해 조건에 맞는 종목을 찾습니다. 결과는 투자 권유나 자동 주문 신호가 아니며, 수집된 로컬 데이터의 최신 시점과 사용자가 선택한 조건을 기준으로 한 후보 목록입니다.

### 기본 사용 순서

1. **필터 조건 추가**로 원하는 필터를 만듭니다.
2. 필터 사이의 **AND** 또는 **OR** 를 선택합니다.
3. 각 필터의 타임프레임, 이동평균선, 기간과 임계값을 설정합니다.
4. **실행**을 누르면 필터별 진행 상태와 남은 종목 수가 표시됩니다.
5. 결과 행을 선택하면 해당 종목의 차트를 확인할 수 있습니다.
6. **랭킹 뷰로 보기**를 누르면 각 필터별 순위와 평균 순위가 표시됩니다.

### 공통 입력값

#### 타임프레임

| 값 | 의미 | 기간 입력 단위 |
|---|---|---|
| 일봉(Daily) | 거래일별 캔들과 일봉 이동평균을 사용합니다. | 거래일 수 |
| 분봉(Minute) | 수집된 1분봉과 분봉 이동평균을 사용합니다. | 1분봉 수 |

예를 들어 일봉에서 `duration=5`는 최근 5거래일을, 분봉에서 `within=60`은 최근 60개의 1분봉을 뜻합니다. 휴장일이나 장이 열리지 않은 시간은 별도 캔들로 계산하지 않습니다.

#### 이동평균선 목록

선택할 수 있는 이동평균 기간은 `5`, `10`, `20`, `60`, `120`, `200`입니다. `20일선`은 최근 20거래일 종가 평균이고, `20분선`은 최근 20개 1분봉 종가 평균입니다. 계산에 필요한 캔들이 부족한 종목은 해당 이동평균을 사용하는 필터에서 제외됩니다.

하나의 필터 안에서는 일봉과 분봉을 섞거나 같은 기간을 두 번 선택할 수 없습니다.

#### 기간: 유지 기간과 최근 N일/분 이내

- **유지 기간(`duration`)**: 조건이 최신 봉부터 연속으로 몇 개 봉 동안 유지되어야 하는지를 뜻합니다. 정배열 유지와 수렴 횡보에 사용합니다.
- **최근 N일/분 이내(`within`)**: 최근 몇 개 봉 안에서 이벤트가 한 번이라도 발생했는지를 뜻합니다. 크로스와 수렴 지점에 사용합니다.
- 일봉은 최대 300봉, 분봉은 최대 390봉까지 조회할 수 있습니다.

### 필터 설명

#### 이평선 정배열

선택한 이동평균선이 화면에 나열된 순서대로 큰 상태를 찾습니다. 예를 들어 `5, 20, 60`을 선택하면 다음 조건입니다.

```text
5 이동평균 > 20 이동평균 > 60 이동평균
```

이 관계가 **유지 기간** 전체에서 계속 성립해야 결과에 포함됩니다. 필터 결과값은 선택한 MA 중 최댓값과 최솟값의 평균 간격 비율이며, 랭킹에서는 간격이 작은 종목이 앞섭니다.

#### 이평선 크로스

단기 이동평균이 장기 이동평균을 교차한 종목을 찾습니다.

- **골든 크로스**: 직전 봉에는 `단기 MA ≤ 장기 MA`였고 현재 봉에는 `단기 MA > 장기 MA`인 경우
- **데드 크로스**: 직전 봉에는 `단기 MA ≥ 장기 MA`였고 현재 봉에는 `단기 MA < 장기 MA`인 경우
- **최근 N일/분 이내**: 지정한 최근 구간 안에서 교차가 한 번이라도 발생하면 포함

필터 결과값은 교차 후 두 MA 사이의 차이를 비율로 표현한 값입니다. 랭킹에서는 크로스 간격이 큰 종목이 앞섭니다.

#### 이평선 수렴 횡보(유지)

선택한 모든 이동평균선이 지정한 **수렴 임계값(%)** 안에 모인 상태가 유지되는 종목을 찾습니다.

```text
(가장 높은 MA - 가장 낮은 MA) / 가장 낮은 MA × 100 ≤ 임계값
```

예를 들어 임계값 `2`와 유지 기간 `10`은 선택한 MA들의 간격이 2% 이내인 상태가 최신 10개 봉에서 계속 유지되어야 한다는 뜻입니다. 랭킹에서는 평균 간격이 작은 종목이 앞섭니다.

#### 이평선 수렴 지점(이벤트)

최근 N개 봉 안에서 선택한 이동평균선의 간격이 수렴 임계값 이하였던 시점이 한 번이라도 있는 종목을 찾습니다. 수렴 횡보가 연속 유지 상태를 찾는다면, 수렴 지점은 최근 구간 안의 발생 여부를 찾습니다. 랭킹에서는 해당 구간의 최소 MA 간격이 작은 종목이 앞섭니다.

#### 외국인·기관 순매수 상위

KIS 투자자 랭킹 API가 반환한 외국인 또는 기관 순매수 상위 종목을 사용합니다.

- KIS API 제약에 따라 최대 30종목만 조회합니다.
- API가 반환한 순서대로 `1위`, `2위`, `3위`가 부여됩니다.
- 다른 필터와 AND로 연결하면 순매수 상위 종목을 먼저 후보군으로 줄인 뒤 나머지 조건을 검사할 수 있습니다.
- 외부 KIS API 상태에 따라 이 필터만 일시적으로 결과가 없을 수 있습니다.

#### 이격도

현재 가격이 선택한 이동평균에서 얼마나 떨어져 있는지 지수로 표현합니다.

```text
이격도 지수 = 현재가 / 이동평균 × 100
```

| 지수 | 의미 |
|---:|---|
| 95 | 현재가가 MA보다 5% 아래 |
| 100 | 현재가와 MA가 동일 |
| 105 | 현재가가 MA보다 5% 위 |

- **이상(above)**: 이격도 지수가 임계값 이상인 종목을 찾습니다. 랭킹에서는 지수가 큰 종목이 앞섭니다.
- **이하(below)**: 이격도 지수가 임계값 이하인 종목을 찾습니다. 랭킹에서는 지수가 작은 종목이 앞섭니다.

OHLCV와 이동평균이 모두 존재하는 최신 동일 시점의 가격을 사용합니다.

#### 최대 거래량 매물대 돌파

현재 봉을 제외한 과거 구간에서 거래량이 가장 컸던 캔들의 고가를 현재 종가가 돌파한 종목을 찾습니다.

| 탐색 구간 | 데이터 |
|---|---|
| 일봉 1개월 | 이전 30개 일봉 |
| 일봉 3개월 | 이전 60개 일봉 |
| 분봉 2시간 | 이전 120개 1분봉 |
| 분봉 4시간 | 이전 240개 1분봉 |

거래량이 같은 캔들이 여러 개면 가장 최근 캔들을 매물대로 사용합니다. 필터 결과값은 현재 종가가 매물대 고가를 넘어선 비율이며, 랭킹에서는 돌파율이 큰 종목이 앞섭니다.

### AND와 OR 조합

- **AND**: 양쪽 조건을 모두 만족하는 종목만 남깁니다.
- **OR**: 어느 한쪽 조건이라도 만족하는 종목을 합칩니다.

여러 조건은 OR을 경계로 AND 묶음이 나뉩니다. 예를 들어 다음 조합은 두 개의 전략 묶음을 합친 결과입니다.

```text
정배열 AND 골든 크로스 OR 이격도 AND 거래량 돌파

= (정배열 AND 골든 크로스)
  OR
  (이격도 AND 거래량 돌파)
```

AND 묶음 안에서는 결과를 바꾸지 않는 범위에서 비용이 낮은 필터가 먼저 실행되어 후보 종목을 줄입니다.

### 랭킹 뷰 계산 방식

랭킹은 검색 조건을 다시 판정하는 점수가 아니라, 이미 검색된 결과를 비교해서 보기 위한 프론트엔드 표시 기능입니다.

| 필터 | 앞 순위가 되는 값 |
|---|---|
| 이평선 정배열 | MA 간격이 작을수록 |
| 이평선 크로스 | 크로스 간격이 클수록 |
| 수렴 횡보·수렴 지점 | MA 간격이 작을수록 |
| 외국인·기관 순매수 | KIS 순위 숫자가 작을수록 |
| 이격도 이상 | 이격도 지수가 클수록 |
| 이격도 이하 | 이격도 지수가 작을수록 |
| 최대 거래량 매물대 돌파 | 돌파율이 클수록 |

각 필터는 **공동 순위 방식**으로 순위를 매깁니다. 값이 같으면 같은 순위를 받고 다음 순위는 건너뜁니다. 예를 들어 `1위, 1위, 3위`가 됩니다. 이후 종목별로 값이 존재하는 필터 순위만 평균하고, 평균 순위가 낮은 종목부터 표시합니다.

OR 결과에서는 어떤 종목이 일부 필터만 만족해 다른 필터 값이 없을 수 있습니다. 이 값은 `-`로 표시되고 평균에서도 제외됩니다. 따라서 서로 다른 개수의 필터로 계산된 OR 종목 간 평균 순위는 동일한 조건 수를 만족한 종목끼리의 절대 점수로 해석하면 안 됩니다.

### 결과 화면 읽기

- **기본 뷰**: 시장, 종목코드, 종목명, 최신 분봉 가격, 전일 종가 대비 등락률, 최신 분봉 거래대금, 시가총액을 보여줍니다.
- **랭킹 뷰**: 각 필터의 순위와 유효한 순위의 산술평균을 보여줍니다.
- 결과 행을 누르면 차트가 열립니다.
- 데이터 수집이나 MA 재구축 중에는 `/health` 외 API가 보호를 위해 일시적으로 503을 반환할 수 있습니다.

더 자세한 요청 형식과 내부 처리 방식은 [`docs/screener.md`](./docs/screener.md)를 참고하세요.

## 🚀 배포 가이드 (Deployment Guide)

본 프로젝트는 GitHub Actions를 활용하여 **완전 자동화된 CI/CD 파이프라인**이 구축되어 있습니다.
로컬 코드를 수동으로 서버에 전송할 필요 없이, 아래 순서에 따라 GitHub 설정만 완료하면 인프라 세팅부터 SSL 발급, 서비스 구동까지 자동으로 진행됩니다.

### Step 1. GitHub Secrets 환경변수 세팅 (가장 중요)
배포를 시작하기 전, GitHub 레포지토리의 **[Settings] -> [Secrets and variables] -> [Actions]** 로 이동하여 `Repository secrets`에 아래 변수들을 반드시 등록해주세요.

| Secret Name | 설명 | 예시 |
|---|---|---|
| **[서버 및 인프라]** |
| `OCI_HOST` | 배포할 오라클 클라우드(OCI) 서버의 공인 IP 주소 | `123.45.67.89` |
| `OCI_USERNAME` | 서버 접속용 SSH 사용자 계정명 | `ubuntu` (또는 `opc`) |
| `OCI_SSH_KEY` | 서버 접속에 사용할 SSH Private Key | `-----BEGIN OPENSSH PRIVATE KEY-----...` |
| `CR_PAT` | 도커 이미지 푸시용 GitHub Personal Access Token | `ghp_xxxxxxxx...` |
| `DOMAIN` | 서버에 연결된 도메인 이름 (Nginx용) | `api.yourdomain.com` |
| **[KIS API 정보]** |
| `KIS_MY_APP` | KIS OpenAPI 실전투자 App Key | `dsgfhh...` |
| `KIS_MY_SEC` | KIS OpenAPI 실전투자 App Secret | `jksdgR...` |
| `KIS_MY_HTSID` | 한국투자증권 HTS 접속 ID | `toM4to` |
| `KIS_MY_ACCT_STOCK` | 주식 계좌번호 앞 8자리 | `12345678` |
| `KIS_MY_PROD` | 계좌 상품코드 뒤 2자리 (종합계좌는 `01`) | `01` |

*(참고: 이 시크릿들은 깃허브 액션이 실행될 때 동적으로 서버에 `kis_devlp.yaml` 과 `.env` 파일을 안전하게 생성하는 데 사용되며, 절대로 코드에 하드코딩되어 노출되지 않습니다.)*

---

### Step 2. 서버 초기 인프라 세팅 (최초 1회 수동 실행)
도커 마운트를 위한 디렉토리를 생성하고, `.env` 환경변수 파일을 세팅한 뒤 HTTPS(SSL) 인증서를 최초 발급받는 작업입니다.

1. 깃허브 레포지토리 상단의 **[Actions]** 탭 클릭
2. 좌측 메뉴에서 **`🛠️ Setup Server & SSL`** 워크플로우 선택
3. 우측의 **[Run workflow]** 버튼 클릭
4. 인증서 발급에 사용할 `Domain Name`과 `Email`을 입력하고 실행!
   - ➔ 서버의 `~/Trading` 폴더에 `.env`와 인프라 파일들이 자동 배치되고 인증서 발급이 완료됩니다.

---

### Step 3. 메인 배포 (자동 실행)
초기 세팅(Step 2)이 끝났다면, 이제부터는 코드 개발에만 집중하시면 됩니다.

1. 로컬에서 코드를 수정하고 **`main` 브랜치에 Push** (또는 Pull Request Merge) 합니다.
2. 자동으로 메인 배포 워크플로우(`deploy.yml`)가 돌아갑니다.
3. 소스코드가 도커 이미지로 빌드되어 GHCR에 안전하게 보관되며, OCI 서버는 가장 최신 이미지를 다운받아 서버를 무중단(또는 짧은 다운타임) 재시작합니다.
4. **HTTPS(443)** 환경에서 동작하는 Zero-Latency API 서버가 켜집니다! 🎉
